# Pre Output Inventory

## Purpose
This file implements TODO task `0.1`: inventory old Pre-generated values and map them to the new `simulation_steps` payload.

Primary rule:
- If the old Pre generated a value, the new Pre must generate it too and expose it from `simulation_steps` or from a direct `simulation_steps` artifact reference.
- Cleanup may remove duplicated source/user/inherited inputs from `simulation_steps`, but must not remove old-Pre-generated output.
- `simulation_steps` should carry minimum ID data and enough status data for troubleshooting.

## Sources Used
- Old output table schema: `backend_old/forgelab/sql_setup/create_tables.py`, `server_pre_main`.
- Old Pre persistence: `backend_old/forgelab/srv_pre/pre_worker_class.py`, `_query_insert_output_into_server_pre_main`, `query_update_server_pre_main_set_output_row`.
- Old Pre output generation examples:
  - billet initialization and first row geometry around `operation_7_geometry`
  - basis propagation and rotation around `_initial_basis` / `_final_basis`
  - feed-plan calculations around `_set_is_press_in_automatic_mode` and feed simulation methods
  - geometry, area, volume, weight, strain, and time calculators near the lower half of `pre_worker_class.py`
- New runtime table: `backend/app/models/workflow_runtime.py`, `SimulationStep` and `SimulationStepStatus`.
- New Pre write path: `backend/app/orchestration/runtime_backend.py`, `_compiled_row_to_step_payload` and `_write_compiled_simulation_step`.
- New compiler row contract: `backend/app/services/preprocessor/compiler.py`, `CompiledControlProgramRow`.

## Current Steps Payload Buckets
The Steps API response is intentionally grouped by provenance so the dashboard can later replace text with icons/diagrams without mixing sources.

| Frontend/API title | Backend field | Current source | Why it exists now | Cleanup decision |
|---|---|---|---|---|
| `simulation_step` | grouped fields from `simulation_steps` | direct table row | This is the primary Pre output/test payload: typed columns, geometry, calculations, timeline, `pre_input`, and `pre_output`. | Keep as the main Steps dashboard data source. |
| `simulation_steps.pre_input` | `simulation_step.pre_input` | compact normalized context from `PreprocessorCompiler._extract_control_parameters` | It carries context consumed by migrated compiler code: direct-parent Deformation values, press/die/material enrichments, feed/speed settings, furnace values, compatibility mirrors, and accumulated parameters. | Keep collapsed by default for troubleshooting. Do not treat as old-Pre-generated output unless a value is transformed by Pre. |
| `simulation_steps.pre_output` | `simulation_step.pre_output` | `CompiledControlProgramRow.operation_specific_parameters` plus runtime identifiers added in `_compiled_row_to_step_payload` | Intended to be the generated operation-specific control-program payload consumed by Solver/Post: final target values, rotations, num of bites, skip bites, feed plan, cut parameters, die gaps, special projections, etc. | Keep as generated Pre output, but clean it: remove `raw_parameters` and source/control dumps after all generated values are explicit. |
| `simulation_step_status` | `simulation_step_status` | runtime `simulation_step_status` row | Mutable runtime/queue/solver state for the same `document_operation_id`. | Show separately from `simulation_step` so users can distinguish Pre output from runtime state. |
| `Diagnostics / API response` | `diagnostics` | API-composed troubleshooting metadata | Contains response-source labels, API messages, and `related_log_query.search_terms`. It is not persisted Pre output. | Keep for troubleshooting, but always label as API context, not `simulation_steps` data. |
| `Related Pre log records` | `GET /logs/pre/related` | local JSONL worker logs | Loaded lazily for the selected step using `document_operation_id` as the primary match key and template/source fields as supporting evidence. | Keep separate from the hot `simulation_steps` list payload so the dashboard can show compact evidence/icons without mixing DB rows and file logs. |

Practical interpretation:
- `simulation_step` answers: "What is stored in `simulation_steps` for this compiled/preprocessor row?"
- `simulation_step_status` answers: "What is the mutable runtime state for this row?"
- `Diagnostics / API response` answers: "Which API-composed context helps troubleshoot this row?"
- `Related Pre log records` answers: "Which local Pre worker log records mention this selected simulation step?"
- Source/user data answers "What did the user/document specify?" and belongs in the Operations view or an explicit trace action, not the default Steps dashboard.

## Classification Rules
- `Generated Pre output`: old Pre calculated or normalized the value. Keep or re-create it in `simulation_steps`.
- `Source/input copy`: old table copied values from `document_operations`, material, press, dies, or document blocks. Prefer `document_operations` or typed FK columns, not repeated JSON dumps.
- `Minimal ID`: keep only when required for sibling identity, traceability, joins, Solver/Post, or UI filtering.
- `Status`: keep in `simulation_steps.calculations` only for Pre output state; use runtime `simulation_step_status` for mutable Solver state.
- `Obsolete old-table state`: old monolithic orchestration/post/solver state that belongs to newer status/task tables, not Pre output JSON.

## Cleanup Candidates After Gaps Are Resolved
Do not remove these until generated-output mapping and tests prove they are not needed.

| Candidate | Why noisy | Safer target |
|---|---|---|
| `pre_input.compiler_values` in migrated old rows | Mostly duplicates compiler-recognized source values preserved during migration. | `document_operations.operation_parameters` plus generated calculations. |
| Excess `simulation_steps.pre_input` source copies | Mostly duplicates direct-parent/source values and enriched library data. | Typed FK columns plus generated calculations/pre-output. |
| `pre_output.raw_parameters` if present | Full source dump, not generated output. | Remove after generated values are explicit. |
| Duplicate IDs inside `calculations` or JSON payloads | Typed columns already carry IDs. | Typed columns only. |
| String labels duplicating IDs | Useful for UI only, but can be joined. | API response enrichment, not persisted Pre output. |
| `parameters_json` in geometry payload | May duplicate source geometry parameters. | Keep only if needed for geometry audit; otherwise use explicit geometry fields and source join. |

## Implementation Order For Stage 0 Cleanup
1. Add tests or a diagnostic script that prints current `simulation_steps` generated payload keys for a selected document.
2. Port or restore missing old-Pre-generated values listed in `Immediate Gaps Found`.
3. Normalize metric names and units.
4. Keep Steps API grouped by provenance: `simulation_step`, runtime `simulation_step_status`, and API `diagnostics`; load related Pre log records through the separate selected-step log endpoint.
5. Remove only duplicated source/input JSON after the generated-output inventory is complete.
